# NSS CTF solution

The useful relation is exposed by subtracting the two public signature products before centering. All calculations below use the negacyclic ring `Z[x]/(x^256 + 1)`; public calculations also reduce coefficients modulo 367.

The key generator uses `f = u + 3*r_f` and `g = u + 3*r_g`. Define the small polynomial `d = (g-f)/3 = r_g-r_f`. Since the public key is `h = g/f` and a signature is `s_i = f*w_i`, the public data determines

```text
D_i = center(3^(-1) * (h-1) * s_i mod 367)
    = d*w_i mod 367.
```

The coefficients of `d*w_i` are much smaller than those of `f*w_i`. If they all lie between -183 and 183, centering recovers the exact integer product, including the negacyclic reduction. This condition is checked directly once the secret is recovered.

The solver builds the integer lattice generated by every negacyclic rotation of `D_0` and `D_1`. These are integer multiples of the shared divisor `d`. Hermite normal form gives a canonical basis of dimension 256, with a determinant of 965 bits. Adding the third signature leaves this basis unchanged. `audit_ideal.py` checks membership for every supplied signature.

Reduction of this ideal lattice seeks a short signed rotation of `d`. Because `h-1` is invertible modulo 367 for this instance, each candidate yields

```text
f_candidate = center(3*d_candidate / (h-1) mod 367).
```

The solver tries the 512 signed negacyclic rotations and checks the exact key-generation coefficient counts. For a valid candidate it derives `SHA256(bytes(coefficient % 256 for coefficient in f))` and decrypts the supplied ciphertext using AES-256-ECB with PKCS#7 padding.

`verify.py` independently checks the public-key equation, all exact ternary weights, all ten signature equations, the unwrapped integer difference products, padding, and an encryption round trip. Successful recovery writes `flag.txt` and `recovered.json`.

The supplied data file has SHA-256 `5dfbcc3ddb74a043d7725e676dd6dcff6c5c0afbf9e818604d01f4307244297b`.

## Files

- `solve_ideal.py`: the integer-ideal recovery pipeline.
- `audit_ideal.py`: independent membership check for every difference product.
- `verify.py`: independent verification of the recovered secret and plaintext.

The earlier public-key and multi-signature modular lattices are unnecessary if the exact integer products above can be recovered. The old notes also contain two errors: a SHA-256 digest supplies a 32-byte AES key, and evaluating a negacyclic residue at 1 does not preserve the ring equations. Reducing chosen modulo-367 representatives modulo 3 does not justify a kernel relation for the secret.
