# Siren - Crypto CTF Writeup

## Overview
**Challenge:** Siren
**Category:** Cryptography
**Vulnerability:** ECDSA Nonce Bias (Hidden Number Problem)

In this challenge, we interact with a server acting as an ECDSA signing oracle over the `secp256k1` curve. The server is willing to sign any message we send, except for one forbidden phrase: `"unlock:release-the-tide"`. 

To retrieve the flag, we must successfully forge a signature for this forbidden phrase and submit it via the `unlock` command.

## The Vulnerability

The vulnerability lies in how the server generates the nonce ($k$) during the signing process:

```python
def shaped_nonce(msg):
    prefix = public_pitch(msg) << SUFFIX_BITS
    while True:
        k = prefix | (rng_below(SUFFIX_BOUND) - 1)
        if 1 <= k < N:
            return k
```

The nonce is shaped by combining a prefix and a randomly generated suffix. 
The `prefix` is computed as follows:

```python
def public_pitch(msg):
    material = (SONG_ID + ":" + msg).encode()
    h = int.from_bytes(hashlib.sha256(material).digest(), "big")
    return h >> (256 - PITCH_BITS)
```

Because `SONG_ID` is public, `PITCH_BITS = 10`, and the message is chosen by us, we know the exact value of the top 10 bits of every nonce generated by the server. 

When a portion of the ECDSA nonce is known for multiple signatures, the private key can be recovered using the **Hidden Number Problem (HNP)**.

## The Mathematics

The ECDSA signing equation is:
$$ s \equiv k^{-1} (z + r D) \pmod N $$

Where:
- $z$ is the message hash.
- $r, s$ is the signature.
- $D$ is the private key.
- $k$ is the nonce.

We can rearrange this equation to solve for $k$:
$$ k \equiv s^{-1} z + s^{-1} r D \pmod N $$

We know that $k$ is composed of our known prefix ($K_0$) and an unknown suffix ($k'$):
$$ k = K_0 + k' $$
Where $K_0 = \text{public\_pitch(msg)} \ll 246$, and $k' < 2^{246}$.

Substituting this back into the equation:
$$ K_0 + k' \equiv s^{-1} z + s^{-1} r D \pmod N $$
$$ k' - s^{-1} r D \equiv s^{-1} z - K_0 \pmod N $$

Let $A = s^{-1} r \pmod N$ and $B = s^{-1} z - K_0 \pmod N$. We now have:
$$ k' - A \cdot D \equiv B \pmod N $$

This forms a system of linear congruences. Because $k'$ is significantly smaller than $N$ (it is bound by $X = 2^{246}$), we can embed these equations into a lattice and use the **Lenstra–Lenstra–Lovász (LLL)** lattice reduction algorithm to solve the Closest Vector Problem (CVP) and find the private key $D$.

## Lattice Construction

For $m$ collected signatures, we construct a lattice basis matrix $M$ of size $(m+2) \times (m+2)$:

1. **Modulo N relations:** The first $m$ rows encode the modulo $N$ reduction.
2. **The $A$ coefficients:** The $(m+1)$-th row contains the $A_i$ terms and is used to multiply with the private key $D$.
3. **The $B$ constants (Target Vector):** The $(m+2)$-th row encodes the $B_i$ constants and the bounding factor $X$.

To properly balance the lattice, we multiply the first $m+1$ columns by a scaling weight $W = 2^{10}$. 

Running the LLL algorithm on this matrix will produce a reduced basis where one of the short vectors reveals the private key $D$.

## Exploitation Workflow

1. **Collect Signatures:** Request ~40 signatures from the server for arbitrary messages.
2. **Build Lattice & Solve:** Use `fpylll` (or SageMath) to apply the LLL algorithm and extract the private key.
3. **Forge Signature:** Once $D$ is known, manually forge an ECDSA signature for `"unlock:release-the-tide"` using a random nonce.
4. **Submit for Flag:** Send the forged $r, s$ values to the `unlock` endpoint.

## Relevant Files

- **`get_flag.py`**: The main exploitation script that interfaces with the server, collects the signatures, and orchestrates the forge.
- **`solve_live_fpylll.py`**: The mathematical backend script that utilizes `fpylll` to construct the lattice and compute the private key.
